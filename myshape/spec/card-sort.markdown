# 設計紀錄：卡片照優先順序或建立時間排列

2026-11-27 定的。使用者要左側欄的議題卡片可以換成照建立時間排，細節交給架構這一側，所以這裡寫的就是決定，沒有開給使用者的選項。拖曳在篩選中怎麼排見[篩選中拖曳](drag-under-filter.markdown)，這份只寫排列換了之後多出來的規則。

## 決定

1. **只改顯示。** 排列只決定左側欄「高」「一般」「待辦」三個佇列裡的卡片由上而下怎麼列。佇列本身、每個議題的位置、`topics.json` 與 aggregator 讀到的優先順序都不動；切換排列不送任何東西給看板（記在視圖裡的除外，見第 7 條）。
   理由：優先順序是派工的順序，只能由拖曳（或 `move`）改，不能因為換個看法就變。
2. **三種排列**：「照優先順序」（佇列的順序，預設）、「新的在上」、「舊的在上」。按鈕在側欄「優先順序」標題下面，不是照優先順序時多一行說明只改顯示、拖曳怎麼算。
   方向做成兩個按鈕而不是一個「反過來」：一眼看得出現在是哪一種，也只有一個地方決定。
3. **只管這三個佇列的議題卡。** 一次一張或自有順序的卡都照舊：「等你決定」（[lifecycle](lifecycle.markdown) 第 4 節的一條佇列）、「要你動手」、側欄的「現在」與「排程」、「已封存」、首頁的「最近的結果」「進行中」「排定的」與未分類區、議題頁。
   理由：那些卡的順序各有它的規則（輪到誰、時刻、新的在上），不是優先順序，換排列沒有意思；「排定的」是首頁的一段，也照它原本的順序。
4. **建立時間是議題的 `created_at`**（`topics.json`，[contracts](contracts.markdown) 第 3.1 節），看板一建立議題就寫。頁面的 `/api/state` 把它放在每個議題的 `created_at`（不是讀取契約，aggregator 讀不到這份資料）。拆分出來的議題是拆分那一刻，合併之後留下的議題用它自己的。
   檔裡沒有這個欄位或讀不懂的（只有手改過的檔會這樣）當成比任何有時間的都舊：「新的在上」排在最下面，「舊的在上」排在最上面。理由：它一定早於看板開始寫這個欄位，而且這樣兩個方向剛好相反，不用另一條規則。
5. **時間相同時照優先順序**，兩個方向都一樣（不跟著反過來）。比的是解讀後的時刻，不是字串。理由：優先順序在同一份資料裡一定有、不會相同，也是使用者切回「照優先順序」時會看到的那個先後。
6. **照建立時間排時，拖曳只能換佇列。**
   - 在原來的佇列裡放下什麼都不送：這時看到的位置不是優先順序，放在哪兩張卡之間都說不出一個使用者看過的優先順序。
   - 拖到別的佇列，排在那個佇列（完整的佇列，連篩選沒列出的與排程議題也算）的最後，請求是 `{id, queue}`，和以前放在佇列尾端的一樣；放下之後卡片照建立時間出現在它該在的位置。
   - 手機一次只看一個佇列，所以手指只能拖到上方別的佇列的分段鈕，排在那裡的最後，請求同上；在清單裡或自己佇列的鈕上放下什麼都不送（[篩選中拖曳](drag-under-filter.markdown)第 8 條）。
   - 拖曳中卡片不跟著游標換位置（只有虛線框），每個佇列的落點提示寫「照建立時間排列中：拖到別的佇列會排在那裡的最後，在原來的佇列裡放下不會改順序」，篩選中加「（連沒列出的也算）」。
   - 照優先順序時跟以前一模一樣，篩選中照[篩選中拖曳](drag-under-filter.markdown)。
   理由：這樣每一次放下得到的優先順序都說得出來，而且是使用者看得到的那一種（「排在最後」），不會悄悄變成另一個順序。
7. **記在哪裡。** 有選了的視圖（篩選面板上那個視圖亮著）時，排列記在那個視圖裡：`hashtags.json` 的視圖多一個 `order`（[contracts](contracts.markdown) 第 3.8 節），在那個視圖上換排列就用同一個 id 再存一次那個視圖（`views/save`，其他欄位照它存的）；「存成視圖」把當下的排列一起存。沒有選視圖時記在這個頁面自己的 `localStorage`（鍵 `myshape.card-order`）。
   看到的排列 = 選了的視圖的 `order`（沒有就是照優先順序），沒有選視圖時是 `localStorage` 的（沒有、讀不到或不認得的值就是照優先順序）。所以從一個視圖改了篩選（它就不再亮），排列也跟著換成頁面自己記的；選回那個視圖又是它的。開看板時套用的預設視圖也一樣。
   不寫進 `topics.json`、`todos.json`、讀取契約（第 4 節）或任何送給 aggregator 的東西。

## 沒有選的做法

- 照建立時間排時拖曳一開始就切回照優先順序：卡片在游標底下整個重排，而且頁面拖曳中不重畫。
- 照建立時間排時照看得到的鄰居換算優先順序的位置：會得到使用者從沒看過的優先順序。
- 照建立時間排時完全不能拖：換佇列這件事本來就說得清楚，沒有理由拿掉。
- 只記在 `localStorage`、不放進視圖：視圖就帶不走它的排列，和使用者說的「跟著視圖」不符。
- 時間相同時照議題 id：`t10` 會排在 `t2` 前面，使用者看不出道理。

## 怎麼做到

- 排列寫成純函式 `myshape/src/page/sort.ts`（`sortCards`、`shownOrder`、`parseOrder`）；照建立時間排時的落點是 `myshape/src/page/drop.ts` 的 `timeDropAnchor`，和 `dropAnchor` 一樣用看板自己的 `topics.move` 測，加上一個固定種子的性質測試（隨機的佇列，放下後只有拖的那個議題動了，而且只會在另一個佇列的最後）。
- 視圖的 `order` 由 `myshape/src/hashtags.ts` 讀寫，`views/save` 沒帶就是照優先順序，帶了不認得的值就拒絕。
- 退回沒有這個欄位的舊版時，下一次存 `hashtags.json` 會丟掉每個視圖的 `order`，回到新版時那些視圖都是照優先順序；`localStorage` 的不受影響。
