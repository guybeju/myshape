# 設計紀錄：篩選中拖曳議題

2026-11-27 定的。hashtag 篩選與存下來的視圖（[stage-5](stage-5-browser.markdown) 首頁第 0 項）讓左側欄的佇列只列一部分議題；這份紀錄定下這時候拖曳怎麼排、為什麼這樣排。使用者把決定交給架構這一側，所以這裡寫的就是決定，沒有開給使用者的選項。

## 決定

1. **篩選只改看到什麼。** 放下不貼、不撕任何 hashtag，不改視圖，除了拖的那一個議題，其他議題的佇列與順序都不動。
2. **篩選中，只在看得到的卡片之間排。** 落點錨在看得到的鄰居上：放在一張看得到的卡下面，議題就排在完整佇列裡那張卡的正後面；放在清單最上面，就排在第一張看得到的卡正前面。所以被篩掉的議題彼此的順序不變，夾在兩張看得到的卡之間的，放下之後還在那兩張之間。
3. **拖到別的佇列用同一條規則**，對照那個佇列看得到的卡。那個佇列在篩選下一張卡都沒有時，排到完整佇列的最後（API 本來的預設），拖曳時的落點提示寫明。
4. **沒有篩選時跟以前一模一樣**：排在下面那張卡的前面，下面沒有卡就排最後，請求也一樣是 `{id, queue, before?}`。
5. **拖曳中看得出正在篩選。** 每個佇列的落點提示（拖曳時才出現）在篩選中寫「篩選中：只在看得到的 N 個議題之間排順序，沒列出的 M 個位置不變」；N、M 是那個佇列列出與沒列出的議題數，沒列出的包含排程議題（它們本來就不列在「待辦」的卡片裡）。沒有看得到的卡時寫「篩選中：這裡沒有看得到的議題，放下會排在沒列出的 M 個之後」，佇列是空的寫「篩選中：放下會排在這個佇列最後」。沒有篩選時照舊是「拖到這裡」。
6. 「現在」與「排程」的卡照舊不能拖。
7. **看板給介面、建議用法，不替 aggregator 決定怎麼用。** 移動的路徑完全不讀也不管 hashtag，socket 的 `move` 沒有多任何欄位：aggregator 經 `move` 改不了 hashtag，也繞不過 hashtag 的鎖與上限。

## 怎麼做到

- 頁面送 `POST /api/topics/move` 時，篩選中多一種落點 `{id, queue, after}`：直接排在 `after` 那個議題的正後面。看板在存檔的同一步才對照當時的完整佇列找 `after`，所以頁面拿到的佇列舊了（別人在這之間移過被篩掉的議題）也不會放錯位置；`after` 已經不在那個佇列裡就拒絕，請使用者等頁面更新後再拖一次。另兩種落點不變：清單最上面送 `before`（第一張看得到的卡），沒有看得到的卡就什麼都不帶（排最後）。
- 只讓頁面送 `after`：`move` 的參數從頁面來（`by` 是使用者）才讀 `after`，socket 來的照舊只看 `before`、`first`、`last`，多帶的 `after` 跟以前一樣被忽略。socket 能送的東西沒有變。
- 為什麼不讓頁面自己算出完整佇列裡的 `before`：那要錨在一個被篩掉、使用者看不到的議題上；頁面的資料舊了，議題就會被插到看不到的地方，而且不會報錯。
- 換算寫成純函式 `myshape/src/page/drop.ts` 的 `dropAnchor`，用看板自己的 `topics.move` 測：有沒有篩選、同一個佇列與跨佇列、篩到只剩一個、放在最上面與最下面、目標佇列沒有看得到的卡，加上一個固定種子的性質測試（隨機的佇列與篩選，放下後只有拖的那個議題動了、被篩掉的順序不變、看得到的順序就是使用者放下時看到的）。

## 邊界情形（落實時補定的）

- **放回原位不送。** 篩選中，卡片放回它開始的地方（同一個佇列、上面還是同一張卡），頁面什麼都不送。照第 2 條的字面，放回原位會把它排到上面那張卡正後面，跳過中間被篩掉的議題；使用者看起來什麼都沒做，順序卻變了。拖曳中頁面不重畫，同一個佇列裡上面那張卡就決定了位置，所以只比佇列與上面那張卡。
- **篩到只剩一個議題時拖回自己的佇列**：就是放回原位，什麼都不動；不會因為「沒有看得到的鄰居」被送到最後。拖到別的佇列照第 3 條。
- **「第一張看得到的卡」不算拖的那張**：落點的上下鄰居從拖曳中的清單讀，拖的卡本身已經在落點上，不會當成自己的鄰居。
- **沒有篩選時的排程議題**：「待辦」不列排程議題，所以沒有篩選時也有看不到的議題。第 4 條優先：沒有篩選就照以前排在下面那張卡前面，不改成錨在上面那張。
- **合併過的議題**：`after` 和 `before` 一樣先找合併後留下的議題。
- **長的佇列**：佇列的清單最高 38vh、超過就捲動，落點提示又在清單最後，捲動時會看不到。篩選中拖曳時，提示固定在清單可見範圍的底部（`board.css` 的 `position: sticky`），所以一直看得到；沒有篩選時照舊。
